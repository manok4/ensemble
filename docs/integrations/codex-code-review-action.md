# OpenAI Codex Code Review on GitHub — Setup

How to install OpenAI's Codex code review on your PRs so reviewer comments arrive automatically. Pairs with `/en-resolve-pr` (which handles the comments after they arrive).

Two distinct paths exist — pick the one that matches your team.

## Path A vs Path B at a glance

| | **Path A — Codex Cloud (managed)** | **Path B — `openai/codex-action@v1` (self-hosted workflow)** |
|---|---|---|
| Where it lives | OpenAI manages it; toggle in the [Codex settings UI](https://chatgpt.com/codex/settings/code-review) | A `.github/workflows/codex-review.yml` you commit to your repo |
| Auth | ChatGPT-account-bound (OpenAI handles billing/auth) | `OPENAI_API_KEY` (or `AZURE_OPENAI_API_KEY` for Azure) |
| Trigger | `@codex review` in a PR comment, or enable auto-reviews per-repo | `pull_request` events your YAML defines |
| Customization | `AGENTS.md` `## Review guidelines` section | Full prompt control + sandbox/safety flags |
| Cost | Bundled with your ChatGPT/Codex plan | Pay-per-use against your OpenAI API key |
| Comment posting | Automatic | You wire a follow-up step (e.g. `actions/github-script`) to post |
| Best for | Solo / small teams already in ChatGPT | Teams that want explicit prompt control or run on Azure OpenAI |

**Recommendation for Ensemble projects:** start with **Path A** if you have a ChatGPT/Codex plan — zero workflow code, and `AGENTS.md` already lives in every Ensemble-set-up repo. Switch to **Path B** when you need custom prompts, scope filters, or run on Azure OpenAI.

## Path A — Codex Cloud (managed)

### 1. Confirm Codex is wired to your repo

Codex Cloud has to be connected to the repo first. If you haven't done this:

- Go to <https://chatgpt.com/codex>
- Connect your GitHub org/repo
- Confirm Codex can see the repo

### 2. Enable code review for the repo

- Open <https://chatgpt.com/codex/settings/code-review>
- Find the repo in the list
- Toggle **Code review** on
- (Optional) Toggle **Automatic reviews** to fire on every PR open + push, or leave off and trigger manually with `@codex review`

### 3. Add review guidelines via `AGENTS.md`

Codex reads `AGENTS.md` at the repo root. Add a top-level `## Review guidelines` section. Example:

```markdown
## Review guidelines

- Don't log PII. Refer to `references/observability-conventions.md` for the structured-log fields we allow.
- Verify auth middleware wraps every route under `src/handlers/`.
- Per `docs/learnings/patterns/`, prefer the project's structured logger over `console.log`.
- Push back on suggestions that violate `CLAUDE.md` rules — cite the specific rule.
- Aim for high-precision findings: 3 important comments beat 15 nits.
```

Ensemble's `AGENTS.md` (generated by `/en-setup`) doesn't include this section by default. Add it once; Codex will pick it up on the next review.

### 4. Trigger reviews

Two ways:

- **Manual:** comment `@codex review` on any PR.
- **Automatic:** with the toggle on, Codex reviews every PR open + push.

Findings appear as inline comments and a summary review — exactly what `/en-resolve-pr` is built to handle.

That's it for Path A. No YAML, no secrets, no workflow.

## Path B — `openai/codex-action@v1` (self-hosted workflow)

Use this when you want explicit prompt control, run on Azure OpenAI, or prefer pay-per-use API billing over a Codex plan.

### 1. Add `OPENAI_API_KEY` to repo secrets

- Repo **Settings → Secrets and variables → Actions → New repository secret**
- Name: `OPENAI_API_KEY`
- Value: your key from <https://platform.openai.com/api-keys>

For Azure OpenAI: name `AZURE_OPENAI_API_KEY` and add a `responses-api-endpoint` input pointing at your Azure resource (see "Azure variant" below).

### 2. Add the workflow

Create `.github/workflows/codex-review.yml`:

```yaml
name: Codex PR Review

on:
  pull_request:
    types: [opened, synchronize]

jobs:
  codex:
    if: github.event.pull_request.draft == false
    runs-on: ubuntu-latest
    permissions:
      contents: read
    outputs:
      final_message: ${{ steps.run_codex.outputs.final-message }}

    steps:
      - uses: actions/checkout@v5
        with:
          ref: refs/pull/${{ github.event.pull_request.number }}/merge
          fetch-depth: 0

      - name: Fetch base and head refs
        env:
          PR_BASE_REF: ${{ github.event.pull_request.base.ref }}
          PR_NUMBER: ${{ github.event.pull_request.number }}
        run: |
          git fetch --no-tags origin "$PR_BASE_REF" "+refs/pull/$PR_NUMBER/head"

      - name: Run Codex
        id: run_codex
        uses: openai/codex-action@v1
        with:
          openai-api-key: ${{ secrets.OPENAI_API_KEY }}
          # Default sandbox + safety; tighten if your runner is multi-tenant.
          # safety-strategy: drop-sudo
          # sandbox: workspace-write
          prompt: |
            Review pull request #${{ github.event.pull_request.number }}.

            Diff: git log --oneline ${{ github.event.pull_request.base.sha }}...${{ github.event.pull_request.head.sha }}

            Focus on:
              - Correctness and bugs
              - Security vulnerabilities
              - Test coverage gaps
              - Performance regressions
              - Adherence to project conventions in CLAUDE.md, AGENTS.md
              - Adherence to filed learnings under docs/learnings/patterns/

            Aim for high-precision findings. Three important comments are more
            useful than fifteen nits — but flag clear bugs and security issues
            no matter how small.

            Respond with a markdown review suitable for posting as a single PR
            comment. Use specific file:line references.

  post_review:
    needs: codex
    if: needs.codex.outputs.final_message != ''
    runs-on: ubuntu-latest
    permissions:
      pull-requests: write
    steps:
      - name: Post review comment
        uses: actions/github-script@v7
        env:
          CODEX_REVIEW: ${{ needs.codex.outputs.final_message }}
        with:
          github-token: ${{ github.token }}
          script: |
            await github.rest.issues.createComment({
              owner: context.repo.owner,
              repo: context.repo.repo,
              issue_number: context.payload.pull_request.number,
              body: process.env.CODEX_REVIEW,
            });
```

The `if: ... draft == false` guard skips review on draft PRs to reduce burn.

### 3. Verify

- Open a PR (or push to an existing one).
- Watch the **Actions** tab — the "Codex PR Review" job should run, then `post_review`.
- The review appears as a top-level PR comment.
- Run `/en-resolve-pr` locally to triage and respond.

If the action runs but no comment appears, check the `run_codex` job's `final-message` output — empty means Codex found nothing actionable (a feature, not a bug).

## Inputs reference (Path B)

The `openai/codex-action@v1` action accepts (most useful subset):

| Input | Purpose |
|---|---|
| `openai-api-key` | OpenAI API key for the Responses API proxy |
| `responses-api-endpoint` | Override URL — set this for Azure OpenAI |
| `prompt` | Inline prompt text |
| `prompt-file` | Alternative: path to a file containing the prompt |
| `output-file` | Path to write Codex's final message |
| `working-directory` | Directory passed to `codex exec --cd` |
| `model` | Model selection (override the action's default) |
| `effort` | Reasoning-effort level |
| `sandbox` | `workspace-write` (default), `read-only`, `danger-full-access` |
| `safety-strategy` | `drop-sudo` (default), `unprivileged-user`, `read-only`, `unsafe` |
| `codex-args` | Extra args forwarded to `codex exec` |

### Safety strategies — pick deliberately

| Strategy | When to use |
|---|---|
| `drop-sudo` (default) | Linux/macOS hosted runners. Removes default user's `sudo` membership before Codex runs. Safe default for `ubuntu-latest`. |
| `unprivileged-user` | Self-hosted runners with a dedicated `codex-user`. Most isolated. |
| `read-only` | Codex inspects but cannot mutate the filesystem. Use when posting reviews only (no inline fixes). |
| `unsafe` | Required on Windows; **never** use on multi-tenant runners. Protects nothing. |

For PR review only (Codex doesn't need to write to the filesystem), `safety-strategy: drop-sudo` + `sandbox: read-only` is the safest combination.

## Azure variant (Path B)

If you run OpenAI through Azure:

```yaml
- uses: openai/codex-action@v1
  with:
    openai-api-key: ${{ secrets.AZURE_OPENAI_API_KEY }}
    responses-api-endpoint: https://YOUR_PROJECT.openai.azure.com/openai/v1/responses
    prompt: |
      ...
```

Same secret-storage steps as `OPENAI_API_KEY`; same workflow shape.

## Trade-offs and operational notes

- **Path A is automatic; Path B is yours.** Path A's prompt is fixed by OpenAI (with your `AGENTS.md` overrides). Path B lets you write the entire prompt — more control, more maintenance.
- **Cost.** Path A bundles into your ChatGPT/Codex plan. Path B bills per request against your OpenAI API key. For a busy repo, Path A is usually cheaper; for an occasional repo, Path B's pay-per-use can be lower.
- **Rate limits.** Path A enforces ChatGPT/Codex plan limits — you can hit them on busy days. Path B has no rate cap beyond your OpenAI API plan.
- **Required-status-check trap.** Don't make the review a *required* status check unless you're sure. Reviews can fail for transient reasons (rate limit, network); merge gating gets brittle.
- **Draft-PR skip.** The `if: ... draft == false` guard above prevents Codex from reviewing every push to an in-progress PR. Mark the PR ready-for-review when you actually want feedback.
- **Posting mechanics differ.** Path A posts inline review comments natively. Path B (as written above) posts a single top-level review comment. To get inline comments via Path B, replace the `post_review` job with `actions/github-script` calls to `pulls.createReview` with `comments: [...]`.

## Pairing with Anthropic's action

You **can** install both — Path A (or Path B) Codex review *and* Anthropic's Claude review (per `docs/integrations/anthropic-code-review-action.md`). Two AI perspectives.

If you do, expect:

- Two reviews per PR (one from each).
- `/en-resolve-pr` triage will surface both in the same numbered list — verdict per comment, regardless of source.
- The cost roughly doubles (each call hits its own plan/key).
- Useful when you want adversarial review (a finding flagged by both has higher confidence) but adds noise on small PRs.

If running both, set Path A's automatic reviews to **off** and trigger manually with `@codex review` when you want a second opinion. That keeps the default flow lean.

## ChatGPT/Codex terms

OpenAI's terms for Codex Cloud (Path A) tie usage to your ChatGPT/Codex plan. The `openai/codex-action@v1` action (Path B) bills against your OpenAI API key under standard API terms — there's no Anthropic-style "OAuth tokens may not be used outside official tools" restriction, since Path B uses an API key, not a subscription token.

## Where this fits in the Ensemble flow

```
/en-plan → /en-build → /en-review → /en-qa → /en-ship
                                                  │
                                                  ▼
                                            [PR opened]
                                                  │
                                ┌─────────────────┴─────────────────┐
                                ▼                                   ▼
                        Codex review fires                Anthropic review fires
                        (Path A or Path B)                (per anthropic-code-review-action.md)
                                │                                   │
                                └─────────────────┬─────────────────┘
                                                  ▼
                                          /en-resolve-pr
                                          → triage, fix, reply, resolve
                                                  ▼
                                              [merge]
```

Either path produces the kind of inline / top-level review comments `/en-resolve-pr` is designed to handle. The 6-verdict triage (`fixed` / `fixed-differently` / `replied` / `not-addressing` / `declined` / `needs-human`) treats Codex and Anthropic findings the same way.
